# wip-ui

wip-ui は、GMO ペパボの共通基盤デザインシステム [inhouse](https://design.pepabo.com/inhouse/) をベースにした React コンポーネントライブラリです。

## inhouse とは

inhouse は、ペパボが展開する複数サービスに共通するデザイン原則・ガイドライン・アセットを統一した共通基盤デザインシステムです。プロダクトデザインとコミュニケーションデザインの両方をカバーし、サービスごとのブランドを維持しながら一貫性を担保します。

詳細は [design.pepabo.com/inhouse](https://design.pepabo.com/inhouse/) を参照してください。

## フレーバー

inhouse の中核となる仕組みが **フレーバー（Flavor）** です。フレーバーは、ブランドごとに上書き可能なデザイントークンの集合で、以下の 5 つのカテゴリで構成されます。

<Table aria-label="フレーバーカテゴリ一覧">
  <TableHeader>

    <Column id="content">内容</Column>
  </TableHeader>
  <TableBody>
    <Row><Cell>**Color**</Cell><Cell>プリミティブカラーとセマンティックカラー</Cell></Row>
    <Row><Cell>**Elevation**</Cell><Cell>影によるZ軸方向の奥行き表現（レベル 0〜6）</Cell></Row>
    <Row><Cell>**Icon**</Cell><Cell>Material Design ベースのアイコングリッド</Cell></Row>
    <Row><Cell>**Sizing**</Cell><Cell>スペーシング、ボタン高さ、角丸、線幅</Cell></Row>
    <Row><Cell>**Typography**</Cell><Cell>フォントサイズ、行間、フォントファミリー</Cell></Row>
  </TableBody>
</Table>

wip-ui では以下のフレーバーが利用可能です。Storybook のツールバーから切り替えて確認できます。

- **Pepper**（デフォルト）
- **Minne**
- **Apollo**
- **Nachiguro**
- **Flippers**
- **Kung-pu**
- **Lolipop**

セットアップ方法は [Getting Started](?path=/docs/introduction-getting-started--docs) を参照してください。

## トークンの 2 層構造

デザイントークンはプリミティブトークンとセマンティックトークンの 2 層で管理されます。

- **プリミティブトークン**: 具体的な値を直接定義（例: `$blue-600: #3e6f99`）
- **セマンティックトークン**: 意味を持つ名前でプリミティブトークンを参照（例: `$informative-color: $blue-600`）

コンポーネントではセマンティックトークンを使用してください。フレーバーを切り替えた際に、プリミティブトークンの値が変わってもセマンティックな意味が保たれます。

## セットアップ

### 1. CSS のインポート

使用するフレーバーの CSS ファイルをアプリケーションのエントリーポイントでインポートします。

```tsx
// 例: Pepper フレーバーを使用する場合
import 'wip-ui/css/pepper.css'
```

利用可能なフレーバーは [Overview](?path=/docs/introduction-overview--docs) を参照してください。

### 2. FlavorProvider の配置

アプリケーションのルートに `FlavorProvider` を配置して、使用するフレーバーを指定します。

```tsx
import { FlavorProvider } from 'wip-ui'
import 'wip-ui/css/lolipop.css'

function App() {
  return (
    <FlavorProvider flavor="lolipop">
      {/* アプリケーション全体 */}
    </FlavorProvider>
  )
}
```

`FlavorProvider` の詳細な API は [Introduction/FlavorProvider](?path=/docs/introduction-flavorprovider--docs) を参照してください。

### 3. コンポーネントの使用

```tsx
import { Button, Typography, Stack } from 'wip-ui'

function MyPage() {
  return (
    <Stack gap="m">
      <Typography component="h1" size="xl" fontWeight="bold">
        ページタイトル
      </Typography>
      <Button color="interactive">アクション</Button>
    </Stack>
  )
}
```

# Elevation

wip-ui のエレベーションは [inhouse のエレベーショントークン](https://design.pepabo.com/inhouse/flavors/elevation/) に基づいています。影（box-shadow）を使って Z 軸方向の奥行きを表現し、要素間の階層関係をユーザーに伝えます。

## レベル

7 段階のエレベーションレベルが定義されています。数値が大きいほどユーザーに近い位置にあることを示します。

## スタックの分類

### Major Stack

画面全体の「地面（ground plane）」を基準とした絶対的な重なり順を定義します。新しいスタッキングコンテキストを作り、z-index の関係を決定します。

### Minor Stack

Major Stack の上に相対的に重なる要素です。

- **On タイプ**: 前の要素の上に積み重なる。新しいスタッキングコンテキストは作らない（例: ボタン、カード）
- **Over タイプ**: スタッキングコンテキストを作り、他の要素の上に浮かぶ（例: ヘッダー、メニュー、ダイアログ）

## レスポンシブ Props

多くのコンポーネントの prop がブレークポイントごとの指定に対応しています。単一の値を渡すと全画面幅で適用され、オブジェクトを渡すとブレークポイントごとに切り替わります。

```tsx
// 全画面幅で同じ値
<Stack gap="m">...</Stack>

// ブレークポイントごとに切り替え
<Stack gap={{ xxs: 's', m: 'l' }}>...</Stack>
```

## Responsive 型

レスポンシブ対応の prop は `Responsive<T>` 型で定義されています。

```typescript
type Responsive<T> = T | {
  xxs?: T
  xs?: T
  s?: T
  m?: T
  l?: T
  xl?: T
  xxl?: T
}
```

指定したブレークポイント以上の画面幅で値が適用されます。未指定のブレークポイントは、より小さいブレークポイントの値を継承します。
