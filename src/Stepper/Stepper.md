# Stepper

申し込みや初期設定のように、順番の決まった複数のステップからなる手続きで、完了したステップ・今いるステップ・これからのステップを並べて示すコンポーネントです。
手続き全体の長さと現在地が一目で分かり、利用者が「あとどれくらいか」を見通せるようにします。
素の `<ol>` に番号と状態の見た目を付けたもので、進み具合を見せるだけの部品です。ステップの中身（フォームや説明）は、使う側で別に置きます。
使用量や処理の割合のような量の進み具合を示すものではありません。量には Meter を使ってください。

## 基本の使い方

```tsx
import { Stepper, StepperItem } from 'wip-ui'

<Stepper activeIndex={1} aria-label="申し込みの手順">
  <StepperItem>プランを選ぶ</StepperItem>
  <StepperItem>アカウントを入力</StepperItem>
  <StepperItem>支払い方法を登録</StepperItem>
  <StepperItem>内容を確認</StepperItem>
</Stepper>
```

## 構成要素

| 部品 | 役割 |
|---|---|
| Stepper | 手続き全体。現在地から各ステップの状態を決める |
| StepperItem | 個々のステップ。ラベルと補足説明を持つ |

## 使う場面

- 3 つ以上のステップを順番に進める手続きで、複数の画面やセクションにまたがるとき（例：サービスの申し込み、独自ドメインの設定、データの移行）
- 途中で待ち時間や外部の作業が挟まり、今どの段階にいるかを示したいとき

## 使い方

### 手続きの形

- [must] ステップは、手続きの実際の順番どおりにすべて並べる。途中のステップを省いたり順番を入れ替えたりすると、番号と読み上げが実態と食い違うため
- [must] ステップ間を移動する手段（「次へ」「戻る」などのボタン）を Stepper とは別に用意する。Stepper は押しても移動しないため
- [should] ステップが 2 つ以下なら Stepper を使わず、「次へ」ボタンや文章で進め方を示す。並べて見せるほどの長さがないため
- [should] ステップは 6 つ程度までにする。それより多い場合は、手続きの分け方を見直す
- [avoid] 順番を問わず進められる作業や、条件によってステップの数が変わる手続きには使わない。並び順と現在地の意味がなくなるため

### 状態

- 現在地より前のステップは完了、現在地は進行中、後ろはこれからのステップとして表示される。状態はステップごとに指定せず、activeIndex で決まる
- 手続きがすべて終わった状態は、ステップの数と同じ activeIndex で表す
- [must] activeIndex は、利用者が実際にいるステップに常に合わせる。画面が進んだのに Stepper が前のままだと、現在地の読み上げが嘘になるため
- [should] 入力に不備があるなど、そのステップに戻って直す必要がある場合は、その StepperItem に isInvalid を指定する

### 向き

- [should] 横幅に余裕があり、ラベルが短い場合は horizontal にする
- [should] 狭い画面や、ラベル・補足説明が長い場合は vertical にする。horizontal では各ステップの幅が均等に割られ、長い文は折り返して読みにくくなるため

### 補足説明

- [should] そのステップで何が起きているか、何をすればよいかを 1 文で添えたい場合は description を使う（例：「証明書の発行を待っています」）

## 文言

- [should] ラベルは、そのステップで利用者がすることを「動詞 + 目的語」で短く書く（例：「プランを選ぶ」「内容を確認」）
- [should] ラベルは 1 行に収まる長さにする。horizontal では折り返すと高さがそろわなくなるため
- [avoid] 「処理中」のような、何をするかが分からない言葉だけにしない

## アクセシビリティ

- [must] aria-label で、何の手続きかを示す（例：「申し込みの手順」）
- 順序付きリストとして読み上げられ、現在のステップには「現在のステップ」が付く。完了したステップには「完了:」、エラーのあるステップには「エラー:」が読み上げ用に付く
- 状態は色だけでなく、番号・チェック・「!」の記号でも区別される

## 実装

- [must] activeIndex は 0 始まりで指定する。先頭のステップが現在地なら 0、すべて完了なら StepperItem の数
- [should] 手続きの状態をデータとして持ち、そこから activeIndex と isInvalid を導く。表示のためだけの状態を別に持たない
